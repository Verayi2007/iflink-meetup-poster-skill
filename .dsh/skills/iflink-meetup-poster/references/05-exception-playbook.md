# 05 · 异常处理 Playbook

> 格式：**症状 → 根因 → 证据（原作轮次）→ 修法（可直接复制的提示词）→ 兜底**。
> 修法里的 `「」` 内为示例值，按当期 spec 替换。

---

## A. 色彩类

### A1 · 整版被参考图的配色带跑（最高频）

- **症状**：参考图是橙/红/蓝，成图也是橙/红/蓝，品牌绿只出现在个别元素。
- **根因**：图像模型对"参考图风格"的权重 ≫ 文字里的颜色描述。
- **证据**：R1 上传橙红参考图 → 整版 `#FE7733`；用户直到 R4 才用"禁止 #FE7733"掰回来。
- **修法**：
  > 整张海报的强调色出现偏移。请把画面中所有不属于下列色值的绿色，统一校正为荧光绿 `#B1FA63`；黑色块与文字统一为 `#242021`；底色为 `#F6F6F1`。橙红 `#FE7733` 可以作为点缀色小面积存在（≤6%）；若它被铺成大面积或压在文字上，收回成点缀或换成荧光绿 `#B1FA63`。除颜色外其余一律保持不动。
- **兜底**：下载 PNG 用设计工具做"替换颜色"（Select by color → Hue 偏移到 88°），比第 3 次重生成更快。

### A2 · 绿色"不够荧光"（偏草绿 / 偏黄）

- **症状**：`#8BC34A`（草绿）、`#D4FF4F`（黄绿）、`#FFF633`（荧光黄）。
- **根因**：模型对"荧光绿"的语义理解分散；"neon green" 常被解成黄绿。
- **修法**：在提示词里补否命题 ——
  > 荧光绿 `#B1FA63`：不是草绿、不是墨绿、不是黄绿、不是荧光黄；R≈177 G≈250 B≈99。
- **验收**：`python scripts/check-palette.py` 的绿占比落在 5–16% 且未归类色 ≤ 12%。

### A3 · 绿色面积失控

- **症状**：绿色 > 20%，整张发土。
- **根因**：模型把"强调色"理解为"主题色铺满"，或把正文也刷成绿。
- **修法**：
  > 绿色只用于：主标题色块、区块标、姓名 chip、时间地点图标、福利笔刷块、装饰涂鸦。文字一律墨黑，不得出现绿色文字。绿色总面积降到画面的 10% 左右。
- **兜底**：设计工具里降低绿图层的不透明度不可行（会脏），正确做法是缩小绿色块。

### A4 · 点缀角色被染成品牌绿

- **症状**：右下角那个小角色变成荧光绿。
- **证据**：R5 用户原话"奶龙还是用原来的颜色呀哈哈哈"（那只小奶龙是呼应"会做推送的奶龙"话题的，不是品牌吉祥物）。
- **根因**：提示词强调"品牌绿"，模型顺手把画面里所有东西都统一成绿。
- **修法**：用 ②-b 修复模板，并加一句 ——
  > 这个角色不属于品牌色系统，它的主色是 `#FED754`（或本 spec 指定的点缀色），不要使用荧光绿。

### A5 · 点缀色抢戏（画面变花）

- **症状**：异色铺到文字或色块上，或出现两三种非品牌色。
- **根因**：模型把"点缀"理解成"再来一个主题色"。
- **修法**：
  > 点缀色只允许出现在小角色与 2–3 个小涂鸦上，面积不超过画面的 6%；且只能从 #FE7733 暖橙 / #B2A1FF 淡紫 里选一个。文字、标题带、副标题带、姓名 chip、图标一律回到墨黑/荧光绿。
- **验收**：`check-palette.py` 里「点缀色」一项 ≤8% 且种类 ≤2。

## B. 内容类

### B1 · 标题/文案丢字

- **症状**：`AI × 创作 × 交流` 变成 `AI × 交流`；`小福利` 变成 `福利`。
- **根因**：整版重生成时模型压缩并列结构；色块宽度有限时它会"顺手删词"。
- **证据**：R3、R4 连续两次丢「创作」；R3 的「小福利」也曾只剩「福利」。
- **修法**：单行局部重绘（②-c），并在提示词里把该行写成
  > 文字必须是完整的五个字符组：`AI` `×` `创作` `×` `交流`，逐字保留，不得删减任何一个。
- **预防**：`kicker` 字段长度校验 + 生成后逐字读。

### B2 · 中文形近字 / 固定搭配被写错

- **症状**：`镣铐` → `镲锜`；`梅庵` → `梅阉`；成语被拆字。
- **根因**：图像模型对生僻汉字的字形编码不可靠，尤其四字固定搭配。
- **证据**：R3 用户原话「黄东迩那句简介里面，'镲锜'两个字有点奇怪」。
- **修法**：
  > 该行文字为「戴着镣铐跳舞」（镣 liào：脚镣；铐 kào：手铐；比喻在限制中创作）。请逐字书写，禁止替换为形近字。
- **兜底**：**文字层后期替换**。这是最可靠的做法：让模型留出空白或接受错字，导出后用设计工具把这几行字重新打一遍（字体用思源黑体 Bold）。

### B3 · 加戏（多出没要求的信息）

- **症状**：多出"联合主办 某某社团""扫码报名""赞助商"。
- **证据**：R1 自作主张加"联合主办 朝松造物创造力社团"，R2/R3 连续两轮才删干净。
- **根因**：模型认为"海报应该有主办方"，属于先验补全。
- **修法**：
  > 画面中只允许出现页眉、标题、副标题、一句话、时间、地点、嘉宾、福利、插画、点缀角色。不得出现主办/联合主办/承办/二维码/报名链接/赞助商。没有出现在文案清单里的任何文字都不要画。
- **机制**：`build-prompt.mjs` 的 E050 会在输入侧直接拦住这类文案。

### B4 · 人物属性错（性别 / 发型 / 身份）

- **症状**：男嘉宾画成女性；4 位嘉宾头像撞脸；发型与本人不符；两位嘉宾性别互换。
- **证据**：R2 用户指出"陈予谦是男的"；API 实测（v2/v4）两位嘉宾的性别还会互换。
- **修法**：
  > 头像形象必须与嘉宾性别一致：罗丽（女，黑色长发）、沁言学术腾飞（男，黑色短发、圆框眼镜）、黄东迩（男，鸭舌帽+眼镜）、陈予谦（男，黑色短发、眼镜）。
- **机制**：spec 里 `gender` 必填（E013），`hair` 选填并直接渲染进提示词。
- **注意**：头像最容易串位，修的时候**一次只点名改一位**，并写明"其余头像保持不变"。

### B5 · 参考图里的旧文案泄漏进来

- **症状**：新海报出现了参考图里的一句话（如"和一群有趣的人，一起聊聊 AI 的更多可能"）或旧角色，尽管本次清单里没有。
- **证据**：API 实测 v2 与 v4 都继承了这句话；v4 还让旧黄色角色回潮。
- **根因**：参考图（img2img / edit 模式）的内容权重很高，模型默认保留它认得的一切。
- **修法**：提示词末尾加 ——
  > 删除参考图里原有的全部文字与旧角色，一个都不要保留；没有出现在【必须逐字出现的文字】里的任何文字都不得出现在画面上。
- **验收**：成图后逐行核对，多出的整行一律按 G1 FAIL 处理。

### B6 · 规范参数被当成画面文字

- **症状**：画面上出现 `40px`、`5.3%`、`65–70%`、`#F6F6F1` 这类数字，甚至画出对齐线和标注箭头。
- **证据**：API 实测 v1（把 3414 字的规范文档直接喂给 qwen-image-2.0）。
- **根因**：生图模型分不清"元指令"和"要画的内容"，尤其当提示词是文档体时。
- **修法**：改用 `--compact` 生成的短指令版（600–900 字、只列内容不列参数），并在末尾写 ——
  > 不要出现任何尺寸数字、百分比、色值、边框线、说明性小字；不要把指令当成画面文字。

## C. 图形 / 资产类

### C1 · 点缀角色变形（"变丑"）

- **症状**：小角色被拉长、变瘦、加毛、眼睛变写实、嘴巴消失。
- **证据**：R6 用户原话"其他都挺好，奶龙怎么变丑了"。
- **根因**：整版重生成时模型按自己的理解重画 IP。
- **修法**：②-b 模板（写死体型、主色 `#FED754`、豆眼+笑眼、橙嘴、白色杯子竖排 `IF.Link`、吸管）。**只重绘这一块，其余冻结。**
- **兜底**：把定稿里这个角色抠成透明 PNG 备用 —— 但注意它只对应那一期的话题，别当成品牌资产复用。

### C2 · Logo 被重绘/变形/换字重

- **症状**：Logo 变粗、字距被改、`IF.` 和 `Link` 一样粗、被加描边。
- **根因**：模型看到 Logo 就"重画一个"。
- **修法**：
  > 页眉的 Logo 必须与上传的 `IF.Link_浅色背景.svg` 完全一致，等比缩放，不得重绘、不得改变字重与字距、不得加描边或投影。
- **兜底**：**永远接受"位置对但 Logo 是假的"，然后后期用官方 SVG 覆盖**。不要为了 Logo 反复重生成整张图。

### C3 · 出现渐变 / 3D / 照片质感

- **症状**：背景有径向渐变、文字有投影、插画有体积光。
- **修法**：
  > 移除所有渐变、投影、发光与 3D 体积感。整张图必须是平涂 + 手绘线稿 + 印刷颗粒的丝网印刷质感，最多两种绿色调（含笔刷边缘的轻微深浅）。
- **验收**：`check-palette.py` 未归类色 ≤ 12%。

### C4 · 版式散架（元素漂移 / 留白不均）

- **症状**：标题带没咬左线、副标题带离标题带很远、嘉宾条目间距忽大忽小。
- **证据**：R9/R10 的 6 条修复指令正是为此。
- **修法**：②-e 的六条统一指令，一次到位。

## D. 流程类

### D1 · 越改越乱

- **症状**：每轮都整版重生成，上一轮修好的地方又被改坏。
- **根因**：没有"锁区域"。
- **修法**：立刻停止整版重生成；回退到最近一版 PASS 的图；后续每轮只用 ②-a 外壳 + 一个具体修改点。

### D2 · 三轮修不好

- **处置**：
  1. 停下，不要再投同样的提示词（模型会给你同一个错误）。
  2. 换策略：把问题元素**从图里拿掉**（例如去掉点缀角色、去掉某位嘉宾），先保结构。
  3. 或换通道：文字层全部后期重排，模型只负责插画。

### D3 · 一次下达多个修改，结果删掉整块

- **症状**：让它"删掉某一行"，它把相邻的副标题、时间地点一起删了。
- **证据**：API 实测 v3 —— 四改点同时下达，结果时间地点整块消失。
- **根因**：局部编辑是"重绘整张 + 局部约束"，多约束互相冲突时模型选择最省事的解。
- **修法**：拆成多轮，每轮一句 ——
  > 只删除「…」这一行，删掉后该区域留白，**不要改动任何其他文字与元素**。
- **补救**：v3 这种丢失整块的，回退到上一版（v2）重来，不要在 v3 上继续修。

### D4 · 需要批量出 10+ 期

- **处置**：走 `scripts/build-prompt.mjs` 循环 + `check-palette.py` 批量闸门；视觉段落完全复用，只换【六、文案】。
- **注意**：批量时最容易出问题的是**嘉宾人数变化导致的节距**（3 位 vs 5 位），需要按人数微调节距提示词。

## E. 兜底策略总表

| 元素 | 模型可控度 | 推荐策略 |
| --- | --- | --- |
| 版式骨架 | 中 | 提示词写坐标 |
| 色彩 | 中 | HEX + 占比 + 脚本验收 |
| 中文文字 | **低** | 逐字校对 → 不行就后期重排文字层 |
| Logo | **极低** | 只用 SVG 覆盖，不指望模型 |
| 点缀角色 | 低 | 独立局部重绘 → 仍不行就贴图 |
| 手绘插画 | 高 | 放心交给模型，是它最擅长的部分 |
