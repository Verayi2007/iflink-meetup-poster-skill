# 04 · 风格校验规则（六道闸门 G1–G6）

## 判定原则

1. **任何一项 FAIL 都不算通过**，哪怕整体"看着挺好"。
2. 每项都要能回答 Yes/No，不能是"感觉可以"。
3. 修一项、验一项；不许"改完一起看"。
4. 校验结果写进交付摘要（见 SKILL.md Phase 6）。

---

## G1 · 内容锁（逐字比对）

**通过标准**：以下 7 项与 `spec.json` **逐字一致**，无漏字、无多字、无换词、无多余标点。

| 项 | 判例（原作翻车） |
| --- | --- |
| 活动名称 | — |
| 主题行 | R3/R4 两次被压缩成「AI × 交流」，丢了「创作」 |
| 时间 | 时段连接号必须是 `–`（en dash），不是 `-` |
| 地点 | 房间号「110 室」必须完整 |
| 嘉宾姓名 | chip 内最多 6 字，超出会被裁切 |
| 嘉宾话题 | 「戴着**镣铐**跳舞」被写成「镲锜」——**中文固定搭配是图像模型盲区** |
| 福利文案 | 「小福利」曾只剩「福利」，标题被吃掉字 |
| Slogan | 「Link the **IFs**, Connect the **D**ots」曾被写成 "Link the Dots, connect the Dots." |

**操作方法**：把成图放大到 150%，用手指逐字点着读一遍，再倒着读一遍（倒读能发现漏字）。

**自动辅助**：

```bash
node scripts/build-prompt.mjs build/spec.json --check-only   # 输入侧拦截
```

## G2 · 配色闸门（脚本量测）

**通过标准**：

| 指标 | 区间 | 实测（定稿） |
| --- | --- | --- |
| 奶油白 `#F6F6F1` | 55–85% | 66.3% |
| 深黑灰 `#242021` | 5–18% | 11.5% |
| 荧光绿 `#B1FA63` | 5–16% | 9.5% |
| 纯白 | ≤ 6% | 3.9% |
| **点缀色合计** | **≤ 8%** | 3.1% |
| **单一点缀色** | **≤ 5%** | 3.0%（暖黄） |
| **点缀色种类** | **≤ 2 种** | 1 种 |
| 点缀色须落在 `#FE7733` / `#B2A1FF` | 板外异色 ≤ 1.5% | — |

```bash
# 交付图（默认，严格）
python scripts/check-palette.py build/poster.png --profile final

# 文字层草稿（渲染通道产物）——跳过点缀色板，只查主色
python scripts/check-palette.py build/rendered.png --profile draft

# 仓库参考基准（旧色板时期的定稿）——板外色只告警
python scripts/check-palette.py assets/reference/final-poster.png --profile baseline
```

> **为什么要分档**：同一套阈值套在不同性质的图上会互相打架。
> 定稿是风格基准：它的暖黄点缀属于定稿时的配色，用 `final` 查它必然 FAIL —— 但参考图本来就不参与配色合规判定；渲染通道只解决文字层，也不该按交付标准判。
> 分档之后：基线能过（带告警）、草稿能过（带说明）、交付图仍然严格。

**点缀色是允许的**：原作定稿就有 3.0% 的暖黄（右下角那只小奶龙），正是它让画面不发闷。判 FAIL 的不是"有异色"，而是：异色超过 2 种、单一异色超过 5%、或异色跑到文字/色块上。

**容忍度说明**：图像模型不会给出精确 HEX。定稿实测绿为 `#B8EC67`（相对 `#B1FA63` 亮度略降），属**可接受**范围；但若变成草绿（`#7CB342`）、黄绿（`#D4FF4F`）、荧光黄（`#FFF633`）即为跑色。

**肉眼判据**：把成图和 `assets/reference/final-poster.png` 并排，眯眼看色块 —— 绿的明度和饱和度应该几乎一致，不能更暗也不能更艳；异色只应出现在那一个小角色附近。

**判例**：原作 R1–R4 整版是橙红 `#FE7733`（照抄参考图），是最严重的跑色；R5 把点缀角色从黄色改成荧光绿，属"点缀色越界"。

## G3 · 版式骨架（叠图比对）

**通过标准**：

- [ ] 所有左对齐元素咬死同一条竖线（基准 x = 54 / 1024 = 5.27%）
- [ ] 绿块与黑块间距 ≤ 14px，形成"一坨"标题组
- [ ] 页眉 Logo 左、slogan 右，slogan 右边缘与正文右界齐
- [ ] 左信息栏不越过 x = 540，右插画不越过 x = 540
- [ ] 嘉宾条目节距一致（±4px），分隔线只跨文字列
- [ ] 底部福利区与点缀角色不互相压字

**操作方法**：把参考图设为 40% 透明度叠在成图上，看主要元素的水平/垂直基准线是否重合。偏差 > 3% 即 FAIL。

**判例**：原作 R9 的 6 条修复里第 3、4 条（瑕疵修复 / 版式秩序）就是针对"边缘错位、留白不均、对齐混乱"。

## G4 · 字体层级

**通过标准**：

- [ ] 全图无衬线体；无书法体；中文只用一种黑体家族
- [ ] 字号层级严格递减：主标题 > 副标题 > 区块标题 > 姓名 > 话题 > 元信息
- [ ] 正文字重 ≤ 700；标题 800–900
- [ ] 同一层级左右对齐、基线齐平
- [ ] 「×」是乘号，不是字母 x；数字用等宽或半等宽

**判例**：原作 R9 第 1 条（字体系统统一）说明成图曾出现"字体混乱、大小不一致、风格冲突"。

---

## G5 · 图形语言

**通过标准**：

- [ ] 色块一律**直角**（标题带 / 副标题带 / 区块标），只有 chip 与图标带小圆角
- [ ] 无投影、无渐变、无发光、无 3D、无金属、无霓虹
- [ ] 插画描边统一 4–5px 纯黑，宽度一致
- [ ] 头像统一：圆框、2.5px 描边、白底、线稿、绿衣
- [ ] 手绘涂鸦只做装饰，不承载信息
- [ ] 整体有印刷颗粒/轻微错位感，无"AI 塑料感"

**判例**：若出现"渐变背景""玻璃拟态""霓虹光效"，直接判 FAIL 并回到风格回锁模板。

---

## G6 · 品牌资产（放大 200% 检查）

**通过标准**：

- [ ] Logo 用官方 SVG 版本，未重绘、未描边、未加粗、未改字距
- [ ] 浅底用黑字版、深底用白字版（用错等于 Logo 消失）
- [ ] Logo 高度与参考图一致（33px @1024 宽），等比不变形
- [ ] Slogan 大小写正确、位置在右上、右对齐
- [ ] 多个 Logo 并排时高度一致
- [ ] 正文出现的 `IF.Link` 用系统字体直打，不用 Logo 字重模拟

## 纠错机制（FAIL → 动作）

| 闸门 | FAIL 表现 | 首选修法 | 模板 |
| --- | --- | --- | --- |
| G1 | 文字错/漏/裁切 | 单行局部重绘 | ②-c |
| G1 | 话题中文被写成形近字 | 重画该行 + 提示词给"正确字 + 释义" | ②-c |
| G2 | 绿偏移 / 点缀色超 6% 或跑出双色板 | 配色回锁 | ②-d |
| G2 | 绿色面积 > 16% | 回锁 + 减少绿色承载（改回"绿块+黑字"而非整段绿字） | ②-d |
| G3/G4 | 版式散、字体乱 | 6 条统一指令 | ②-e |
| G5 | 出现渐变/3D/照片感 | 风格回锁（强化"手绘线稿/粗描边/无渐变"） | ②-a + 负向清单 |
| G6 | Logo 变形 | 不接受，后期替换官方 SVG | 人工 |
| 任意 | 连修 3 轮仍未过 | **退回上一版 PASS 的图**，不要在当前版继续叠加 | — |

## 交付前的最终三问

1. 把这张图缩小到手机屏幕 1/3 大小，**第一眼看到的是不是活动名**？
2. 遮住插画区，**信息区是否依然完整可读**？
3. 把它和系列里上一期并排，**是不是一眼同一套**？
